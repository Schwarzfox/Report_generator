------------------------------------------------------------------------
1. THE THREE FILE TYPES
------------------------------------------------------------------------

(A) NORMAL SINGLE MEASUREMENT  ->  measurement-<sampleName>-<timestamp>.json
    - THIS IS THE FILE THE REPORT GENERATOR USES.
    - Flat JSON: the measurement object is the top-level dict.
    - metadata.measurementType == "single"
    - Self-contained: contains calibration name, all results, spectrum,
      acquisition settings, hardware identity, dates/times.
    - ~46 KB.

(B) HEAVY "LMM" EXPORT  ->  lmm-<sampleName>-<timestamp>.json
    - Same measurement, but NESTED under a "measurement" key, PLUS the full
      "method", "instrument_calibration", "health_check", "dynamic_hardware"
      blocks (calibration internals + thickness curves).
    - ~551 KB. The large size is calibration reference data, NOT report data.
    - We do NOT need this file for the report. It is only useful if we ever
      want the raw calibration definition (e.g. method.index.quickID "1-00057").

(C) BATCH AVERAGE  ->  measurement-none-<timestamp>.json
    - Only produced for REPEAT measurements (averaging a group of shots).
    - metadata.measurementType == "average".
    - Contains pre-computed per-layer / per-element statistics:
        average, average_std_in_units, average_min_in_units,
        average_max_in_units, average_count.
    - Lists the source shot ULIDs in averagedFromMeasurements[].
    - HAS NO calibration name and NO spectrum, so it cannot drive a report
      on its own.
    - DECISION: we compute our OWN repeat-measurement statistics (mean, SD,
      RSD%, min, max, count) from the individual normal files, because this
      file omits RSD and the calibration name. This file is ignored.

------------------------------------------------------------------------
3. IMAGES — NONE EXIST
------------------------------------------------------------------------
A full recursive scan of every key AND every string value across all three
files (image, photo, picture, thumbnail, jpg, jpeg, png, bmp, base64,
data:image, snapshot) returned NOTHING.

The device hardware DOES have cameras (hwSerialNumbers.narrowCameraSn,
wideCameraSn) and a positioning laser, but no camera image is stored in the
JSON exports.

=> The only "image" the report can show is a SPECTRUM CHART rendered from
   rawSpectra[0].values. Any real sample photo would have to be uploaded
   manually (or come from a separate file the device may save elsewhere —
   unconfirmed).


------------------------------------------------------------------------
4. GROUPING RULE FOR REPORTS
------------------------------------------------------------------------
Group measurements into the same report by EXACT match on calibration:
  - Group key:  methodUlid  (unambiguous)
  - Display label: metadata.analysisResultMetadata.method.name ("Au/Fe")
Measurements spanning multiple calibrations -> one separate PDF per group.
Repeat statistics (mean, SD, RSD%, min, max, count) computed by us across
the normal files that share a calibration.
